# 搜索日志归档

`research/search_log.jsonl` 是当前活动日志。当其达到 5,000 条有效查询或 2 MiB 时，停止向该文件追加，把完整内容原样封存为：

```text
search_log-QRY-<first>-QRY-<last>.jsonl
```

然后创建新的空 `research/search_log.jsonl` 继续记录。归档文件必须满足与活动日志相同的 schema，并遵循以下规则：

- 不拆分单条 JSONL 记录，不改写、重新排序或删除历史查询。
- 查询 ID 在活动日志和全部归档之间保持唯一；新日志从未使用的下一个 ID 开始。
- 修正旧查询时追加新 `QRY` 并使用 `supersedes_query_id`，不修改归档。
- 归档前后检查行数、首尾查询 ID 和文件摘要；摘要只用于发现意外变化，不替代来源真实性核验。
- 仅归档脱敏且允许提交的结构化日志；受限查询内容不得因归档而获得提交授权。
- 超过阶段一证据总存储预算时停止新增检索，先压缩重复摘要；不得删除查询、冲突、不利证据或仍被引用的 ID。

验证器会对活动日志给出轮转预警，并按同一 schema 检查全部归档及活动日志中的全局查询 ID 唯一性。归档文件一旦提交即视为历史证据；需要修复时新增归档或查询记录，不倒改既有内容。
