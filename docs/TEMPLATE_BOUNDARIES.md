# 模板与动态内容边界

本文档是仓库内容归属、生成时机、修改权限和提交方式的事实来源。它用于区分模板预置规则、Codex 与用户协作生成的研究内容、用户本地管理的敏感内容，以及实验程序生成的不可变证据。Codex 在创建、修改、删除或提交文件前应先按本文档判定类型。

## 内容类型

- **模板预置内容**：稳定的目录、规则、格式、安全边界和可复用能力。仅在用户要求维护模板，或研究工作流、结构或公共约定实质变化时修改。
- **动态研究内容**：在用户确认的研究合同和阶段门禁内，由 Codex 填写或生成的计划、代码、实验实现、分析和论文内容。
- **用户本地内容**：凭据、受限数据、受限模型、本地访问权限和机器配置。用户负责准备，Codex 不得读取或输出真实凭据，不得绕过访问控制。
- **运行时证据**：实验程序在实际执行中生成的命令、配置快照、环境、日志、指标和产物。必须脱敏、保留历史，生成后不得覆盖或倒改。
- **可选交付物**：正式 LaTeX、专利材料或其他需要新授权的内容。只在用户明确要求后生成或修改。

## Codex 操作规则

1. 在动态生成内容前，先检查 `docs/WORKFLOW_GATES.md`、`RESEARCH.md` 和当前阶段对应的 TODO；门禁未通过时不得超前生成后一阶段内容。
2. 可以自主完成已授权研究范围内的动态文件、代码和运行记录；不因为它们不存在而要求用户手工创建。
3. 模板规则只在修改工作流、结构、公共能力或安全边界时更新；单次实验不应把临时细节写入根 README、AGENTS 或 `docs/`。
4. 新外部服务或配置仅在研究计划已确认后加入 `.env.example`；只添加变量名和非敏感占位值，真实配置由用户写入本地 `.env`。
5. 保护运行时证据的不可变性。修复脚本、配置或评测后必须使用新运行 ID，不得反向修改旧指标以配合论文。
6. 正式 LaTeX、专利、数据外发、新费用、新访问权限或研究范围扩展需要新的用户授权。
7. 路径未被本表或最近目录 README 分类时，不要根据空文件、旧配置或命名猜测用途；先查找引用和历史，仍不明确时将其作为模板维护决策处理。
8. Skill 的发现、阶段适用性、授权和停止规则遵循 `docs/SKILL_USAGE.md`；阶段本身不是自动调用 Skill 的充分条件。
9. 根目录不再使用 `TODO.md`；不得重新创建兼容副本或在多个文件重复维护全局阶段状态。

## 依赖边界

模板核心依赖只保留多数目标项目都需要的公共能力。单一课题、方法、数据源、模型、评测或交付格式所需包属于动态研究环境，不自动成为模板永久依赖。

增加或删除依赖前，Codex 必须与用户确认以下信息：

- 依赖的具体用途、所支持的任务与不引入时的替代方案。
- 直接与间接安装体积、安装时间、网络下载、缓存和磁盘影响。
- Python、操作系统、CUDA、GPU、CPU 或其他平台约束。
- 版本或上游来源、许可证、供应链风险与是否需要额外凭据。
- 它是模板核心依赖、研究项目依赖，还是适合按需安装的可选能力。

GPU 框架、OCR 系统、绘图套件、模型运行时与厂商 SDK 等大型或平台相关依赖默认先评估按需安装、可选依赖组或更轻量替代方案。删除现有依赖前必须检查源码、脚本、Skills、文档、锁文件与已确认计划，不得仅根据当前导入搜索结果判定“无用”。

依赖变更必须作为一个原子更改处理：同步修改 `pyproject.toml` 和 `uv.lock`，在 `RESEARCH.md` 记录已确认的课题级决策，在受影响阶段的 TODO 中记录待办或完成状态，然后执行 `uv sync` 和相关导入或可执行验证。不在依赖 URL、索引配置、锁文件或日志中写入凭据。

## 排除的旧入口

- 根目录 `main.py` 和项目元数据中的 `research` 命令不属于当前 Codex 工作流，不是必需文件、用户入口或验证目标。
- Codex 在正常研究任务中忽略这两个旧占位入口，不自行实现、调用或要求用户运行。只有用户另行提出专门的维护任务时，才重新评估其删除或实现方式。

## 边界变更

当新增目录、文件类型、外部服务、可选交付物或提交规则时，先更新本文档，再同步检查根 `README.md`、`AGENTS.md`、`.gitignore` 和相关子目录 README。用户的当前指令可以授权一次明确的模板维护任务，但不取消凭据、隐私、许可证、不可变证据和其他安全边界。
