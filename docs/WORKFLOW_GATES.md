# 三阶段工作流门禁

本文档是调研与设计、实验与分析、论文写作三个阶段的进入、完成、停止、恢复和回退规则。机器状态以 `workflow/state.json` 和追加式 `workflow/transitions.jsonl` 为准，`RESEARCH.md` 顶部只保存其可读投影；阶段二和阶段三任务分别写入 `experiments/TODO.md` 与 `paper/TODO.md`。所有切换必须由 `scripts/transition_workflow.py` 在目标门禁预检通过后事务式提交，不得手工提前推进或为了自动推进而绕过门禁。

## 通用状态与原则

每个阶段使用以下状态：

- `未开始`：尚未进入该阶段。
- `进行中`：进入条件已满足，正在执行阶段任务。
- `已暂停`：命中停止条件，等待明确的恢复条件。
- `已完成`：完成条件均已满足或未完成项已获得用户明确的范围调整，并留有记录。

通用规则：

1. 进入条件未满足时，不得启动后一阶段的实质性工作。
2. 需要新的用户决策、授权、凭据、受限数据访问或范围扩展时，Codex 必须暂停并请求用户处理，不得自行假设。
3. 阶段二记录实际执行所需的调用、耗时和费用，并执行付费、外发、凭据和失败停止门禁。资源中断、负面结果或未达到目标指标不等于研究失真，若预定验证已完成且证据完整，可以如实结束阶段。
4. 任何停止都应在 `RESEARCH.md` 记录原因和恢复条件，并在受影响的阶段 TODO 中记录已完成和未完成工作；不得删除已生成的失败证据。
5. 研究问题、数据、指标、阶段二资源方案或范围发生实质变化时，先在 `RESEARCH.md` 记录决策，再回退到最早受影响的阶段重新检查门禁。

## 数据、隐私与外部传输门禁

数据访问和外部 API 调用必须同时满足凭据安全与数据安全：

- 在 `RESEARCH.md` 记录数据的来源、版本、许可证、数据分类、个人信息、内部或受限属性、公开限制与保留/删除要求。
- 在任何数据发送到外部 API 前，明确记录是否允许外发、允许范围、必要的脱敏方式和用户授权。未确认时默认不允许外发。
- 只传输完成实验所必需的最少数据；不在提示词、日志、截图、配置快照或运行元数据中保存密钥、完整环境变量、个人信息或受限样本。
- 外部 API 的输出也视为待检查数据；写入运行产物或论文前检查是否复现敏感内容。
- 存在许可证、隐私、保密性或外部服务条款疑问时，暂停相关工作并请用户确认；不将未确认的数据用于 API、实验或论文。

## 阶段一：调研与设计

阶段一内部状态与方向形成遵循 `docs/PHASE_ONE_PROTOCOL.md`，正式检索与真实性遵循 `docs/SEARCH_PROTOCOL.md`。正常顺序为 `INTAKE → DIVERGE → SEARCH → COMPARE → DRAFT → CONFIRM → GATE_CHECK`。`DIVERGE` 的最初 1–3 轮为 Ultra 方向专用窗口，不产生仓库写入；方向交接后切换 Medium，一次性持久化并继续后续状态。只有达到 `GATE_CHECK`、严格验证通过并获得进入阶段二的明确确认后，才可完成阶段一。

### 进入条件

- 用户已提出研究种子，或明确希望 Codex 协助完善方向。
- Codex 已阅读 `RESEARCH.md`，并区分已确认信息与阶段一未决项。
- 当前动作需要 Skill 时才按 `docs/SKILL_USAGE.md` 选择；阶段名称本身不触发 Skill。
- 不需要用户在对话中提供密钥或其他真实凭据。

### 完成条件

- `RESEARCH.md` 已明确唯一研究方向、创新性依据、最小可证伪路径、范围边界和研究设计。
- 六项方向形成字段已经处理；Medium 已把 Ultra 交接压缩为一条精简交互记录，没有从宽泛方向直接跳到最终合同。
- Codex 已检查实质替代方向。存在真实分叉时比较正式入围方向；不存在真实分叉时保留单方向压力测试说明，不制造虚假候选。
- 恰好一个正式方向为 `已选定`；其他正式方向为 `已否决` 或 `已合并` 并具有理由。
- 研究设计确认字段已记录当前值、信息来源、确认状态和适用的决策/证据引用。
- 真实研究问题、决策、未决问题、来源、调研主张、授权和阶段切换使用 `RESEARCH.md` 声明的稳定 ID，且不存在重复定义或断裂引用。
- 正式验证查询已在 `research/search_log.jsonl` 记录；正式来源、最小主张和持久决策分别登记在 `sources.yaml`、`claims.yaml` 与 `decisions.yaml`。非正式 IDEA 的轻量侦察不要求完整覆盖。
- 搜索停止已有可观察依据：入选方向必须达到证据饱和；被可行性阻断的候选方向可在保留阻断证据和未覆盖范围后停止，不得伪造饱和代理或声称“完全检索”。
- `RESEARCH.md` 中的 `SRC`、`CLM` 和 `DEC` 引用均可解析到阶段一证据层；关键主张优先使用一级或二级、可定位、原始和相互独立证据，二手来源已追溯原始出处，同源转载未计为独立证据。
- 每项拟进入合同的主张已核验 URL/DOI、具体支持位置、数字、单位、日期、版本、适用范围、因果措辞和模型推论边界。冲突及不利来源没有被删除，冲突类型和可能原因已记录；证据不足的内容保持未决。
- 每个研究问题均已关联数据、baseline、指标、成功标准与计划实验；每项预期贡献均已关联比较 baseline。
- 正式计划使用的数据来源、版本、许可证、隐私分类、外部传输边界和公开限制已确认。
- 阶段二实际计划使用的 API/GPU 职责、模型、数据流和失败停止规则已确认；没有计划使用的资源不创建占位字段。
- 活动搜索日志按维护阈值轮转，长内容按最小披露规则压缩，并回查原始来源确认压缩前后一致；关键限制、授权、否决方案、冲突、不利证据和引用 ID 均保留。
- 只有实际计划触发的依赖变更、付费、外部传输、受限访问或授权型 Skill 已登记并确认。
- 范围外事项与阶段一交付物已明确。
- `RESEARCH.md` 的精简活动区已记录当前方向、替代检查、关键未知和下一步。
- `experiments/TODO.md` 已生成可执行的阶段二任务，每个实验任务引用相同的研究问题 ID 与成功标准 ID，并在 `RESEARCH.md` 中记录用户对研究合同的确认或预先授权。

### 停止与恢复条件

任一必需完成项缺失、最终方向不唯一、正式证据引用断裂、创新性反证尚未处理、研究设计无法执行，或即将发生的付费、外发、受限访问、依赖变更等动作没有限定授权时暂停。没有相关高风险动作时，不因缺少授权占位或“不适用”说明而阻塞。

## 阶段二：实验与分析

### 进入条件

- 阶段一已完成，且 `RESEARCH.md` 中不存在会影响实验执行的关键未决项。
- 数据、模型、baseline、指标、API/GPU 分工、实际资源计量方式、付费授权和外部数据传输授权已登记。
- 当前实验具有独立脚本计划、唯一实验 ID、明确输入输出、新的运行目录和可验证指标；`experiments/registry.yaml` 条目关联已确认的研究问题、成功标准和决策 ID。
- 运行前预检已按 `AGENTS.md` 和 `experiments/scripts/README.md` 完成，只报告所需 API 变量“已配置”或“缺失”。
- 参与实验的 Skill 已满足依赖、许可、隐私、外发和付费授权门禁，且不会代替实验脚本或运行记录。

### 完成条件

- 预先确认的 baseline、主要实验、消融与稳健性验证已执行，或已记录用户确认的取消原因。
- 每个成功或失败运行都有不可变记录，且命令、配置、环境、日志、元数据、指标与失败原因符合 `experiments/runs/README.md`。
- 日志、输入摘要、模型输出和产物已完成密钥、个人信息和受限数据检查。
- 分析已覆盖负面结果、失败、异常值和局限，且所有实证结论可追溯到实验 ID。
- `experiments/registry.yaml` 与本地运行目录已完成双向核对：登记的运行均存在、运行归属一致、完成状态至少有一个本地成功运行，所有本地运行也均已登记。
- `experiments/TODO.md` 已更新实验任务状态，并形成 `experiments/evidence_handoff.yaml`；该交接清单明确研究问题、成功标准、实验和运行 ID、可支持与不可支持的主张、负面结果、局限，并将本地证据核验和 registry 对账标记为完成。
- 每个长时任务在启动前创建 `workflow/tasks/<task-run-id>/`，运行时至少每 30 秒刷新结构化进度与心跳；结束时将状态、事件和心跳快照归档到不可变运行目录。

### 停止与恢复条件

遇到资源或凭据缺失、GPU 不可用或显存不足、API 重试达到预定失败阈值、付费或外发授权不成立、数据损坏、指标实现错误、隐私或许可证风险、研究范围变更或用户暂停时，立即停止相关工作。状态文件必须立即写为 `blocked` 或 `failed`，包含已保存检查点、失败原因和恢复条件；保留失败运行，不得把部分结果标记为成功。在资源、授权、数据或计划已修复并记录后，使用新的运行 ID 恢复；不覆盖原运行。

### 可见执行进度

- 数据下载、API 生成、训练、评测和分析分别作为可识别步骤，记录当前实验、seed、完成数/总数、百分比、最近检查点和心跳。
- API 任务记录调用、成功/失败、重试、估算费用和限流；GPU 任务记录设备、训练 epoch/step、GPU 时间和峰值显存。无法可靠获得的数值明确为 `null`，不得猜测。
- Codex 每 30–60 秒轮询 `scripts/manage_task_progress.py list --stage stage_two` 并向用户给出简短更新。超过 120 秒未刷新心跳视为异常并立即说明，不再以无终端输出推断任务仍正常。

## 阶段三：论文写作

### 进入条件

- 阶段二已完成，或用户已明确确认对当前完整证据撰写负面、未完成或局限性报告。
- 每个计划写入的数值、表格、图像和实证结论均有实验 ID 与可核验运行记录。
- 参考文献可核实，数据、模型和外部 API 的许可证、引用、披露和公开限制已确认。
- 运行产物和预计写入内容已检查密钥、个人信息、内部信息和其他受限内容。
- 计划使用的 paper Skill 已回查原始来源；DOCX、PPTX、XLSX 或生成 PDF 等可选交付格式已获得用户明确要求。

### 完成条件

- `paper/draft_zh.md` 中本轮要求的章节已完成，结果、方法、局限性和负面结果表述与实际证据一致。
- 所有数值、表格和图像已标注数据来源、实验 ID，图像具有可复现生成脚本或可编辑源文件。
- 参考文献已核实，外部模型与本地模型的非敏感名称、用途和实验 ID 已披露。
- 所有 `TODO` 已完成、删除或明确说明保留原因，并完成隐私、凭据、许可证与公开边界检查。
- 用户已确认工作草稿达到本轮交付要求。正式 LaTeX 和专利材料不属于默认完成条件。
- 每次实质性写作会话在 `paper/sessions/<session-id>/` 保留状态、事件和心跳，完成状态与本轮章节清单一致。

### 停止与恢复条件

存在缺少实验支撑的结论、与运行记录不一致的数值、无法核实的引用、不可复现图表、隐私或保密风险、未解决许可证/公开限制，或需要用户授权正式 LaTeX/专利工作时暂停。需要新证据时回退到阶段二；需要重新定义问题、指标、数据或范围时回退到阶段一，并重新打开受影响的研究问题、决策和下游确认。不得通过编造、推测或删除不利证据来解除停止。

### 可见执行进度

- 将证据交接核对、提纲、逐节起草、引用核验、结果表/图核验、限制检查和交付检查作为明确步骤；有确定任务数时报告完成数/总数，没有可靠分母时只报告步骤和检查点，不按字数虚构百分比。
- 每次写作会话使用 `paper/sessions/<session-id>/`，至少每 30 秒刷新心跳，并记录当前章节、已核验主张数、引用数、输出位置、证据缺口、阻塞原因和恢复条件。
- Codex 每 30–60 秒轮询 `scripts/manage_task_progress.py list --stage stage_three` 并向用户报告；发现证据缺口时先写入 `paper/TODO.md` 和会话状态，再按门禁回退，不得静默停在一份薄草稿上。

## 阶段切换记录

每次进入、完成、暂停、恢复或回退时：

1. 调用 `scripts/transition_workflow.py`；工具在同一事务中更新 `workflow/state.json`、追加 `workflow/transitions.jsonl`，并更新 `RESEARCH.md` 的状态投影和“阶段切换记录”。不得手工只改其中一个文件。
2. 将影响研究合同的用户确认、范围变更或风险决策记录到 `RESEARCH.md` 的“当前决策”。
3. 阶段一同步维护 `research/` 中的查询、方向覆盖、来源、主张、决策与资源证据；阶段完成时只压缩重复叙述，不删除仍被引用的 ID、来源冲突或不利证据。
4. 阶段二更新 `experiments/TODO.md`，阶段三更新 `paper/TODO.md`；阶段任务文件不得复制运行日志或论文正文。
   两个 TODO 文件保持原有任务记录方式，不作为实时状态投影；心跳、step、sample、epoch、百分比和即时资源消耗仅写入对应的结构化进度目录，进度工具不得自动改写 TODO。
5. 保留既有实验运行和论文证据；新计划不得覆盖或倒改历史结果。
6. 只有门禁已通过且不需要新的用户授权时，Codex 才可按已确认的计划自主继续。

阶段切换记录必须连续。最新 `TRANS-<nnn>` 的新阶段或子状态必须与顶部当前状态一致；不得缺少 `CONFIRM → GATE_CHECK → 阶段二 → 阶段三` 中间记录。回退使用新的 `TRANS` 和必要的取代决策，不能改写旧记录。若阶段一门禁未通过、关键 TODO 未解决、搜索覆盖未完成或证据存在阻断冲突，阶段二与阶段三均不得标记为进行中或已完成。
