# 文档目录

`docs/` 只存放稳定、可复用、跨越多个研究阶段的说明与规范；不要放当前待办、临时调研笔记、运行日志或论文草稿。

## 当前约定

当前项目的入口与工作状态位于：

- 根目录 `README.md`：项目使用说明。
- 根目录 `RESEARCH.md`：唯一的研究任务合同。
- 根目录 `TODO.md`：当前待办事项。
- 根目录 `AGENTS.md`：Codex 必须遵守的长期规则。
- `WORKFLOW_GATES.md`：三阶段的进入、完成、停止、恢复、回退与隐私门禁。
- `SKILL_USAGE.md`：仓库级 Skills 的发现路径、三阶段使用规则、授权与停止条件。
- `TEMPLATE_BOUNDARIES.md`：模板预置、Codex 动态生成、用户本地内容、运行证据与可选交付物的权威边界。

## 文档维护规则

每次仓库内容变更后，都应检查根目录 `README.md` 和 `AGENTS.md` 是否仍与实际结构、使用方式和维护约定一致。子目录变更先更新其自身 README；只有当变更影响根目录导航、用户使用方式或 agent 工作流时，才同步更新根目录文档。`AGENTS.md` 中的 `Documentation Update Policy` 是该规则的英文权威版本。

因此，在实际需要出现前，本目录无需预先创建大量协议文件。

## 建议按需新增的文档

| 文件 | 适用时机 | 内容 |
| --- | --- | --- |
| `EXPERIMENT_PROTOCOL.md` | 开始系统性运行多个实验时 | 实验状态、目录、配置快照、失败重试与结果登记规则 |
| `ARTIFACT_SCHEMA.md` | 引入计划、注册表或结果清单等结构化文件时 | 字段、版本与校验约定 |
| `DATA_POLICY.md` | 使用受限、可分发或隐私相关数据时 | 来源、许可证、存储、访问与引用规则 |
| `REPRODUCIBILITY.md` | 准备发布代码、结果或论文时 | 环境、随机种子、数据/模型版本及复现步骤 |
| `SECURITY.md` | 使用 API 密钥、数据库或外部服务时 | 凭据、日志脱敏、预算与网关规则 |

新增文档应满足两个条件：内容不会随着单次实验频繁变化，并且由多个脚本、实验或写作环节共同遵循。否则请放在 `TODO.md`、`paper/`、`experiments/` 或对应的数据目录中。
