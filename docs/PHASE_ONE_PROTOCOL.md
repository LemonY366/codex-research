# 阶段一交互、确认与恢复协议

本文档是阶段一“调研与设计”的状态机、用户确认和跨会话恢复协议。`docs/WORKFLOW_GATES.md` 决定阶段能否进入、完成、暂停、恢复或回退；本文档决定阶段一内部按什么顺序收集意图、发散方向、调研、比较、形成合同并确认。当前有效合同写入 `RESEARCH.md`；阶段一机器子状态写入 `workflow/state.json` 并投影到 `RESEARCH.md`；详细调研证据写入 `research/`。

## 基本原则

1. 第一阶段的研究目标不是模板预置值，而是用户与 Codex 交互后形成的当前有效合同。
2. Codex 主动通过逐轮问题帮助用户发现和区分研究方向，也可以提出候选方案、执行已授权调研、整理证据和检查一致性；但不能替用户确认最终方向、数据权利、指标取舍、阶段二资源方案或高风险授权。
3. 状态推进以持久化输出和明确确认作为依据，不以对话轮数、回答长度或删除 `TODO` 作为依据。
4. 任一状态发现更早阶段的前提不成立时，回到最早受影响状态；不得通过猜测补齐字段。
5. 每轮结束前更新 `RESEARCH.md` 的“会话恢复摘要”，使下一会话不依赖完整聊天历史即可恢复。

## 状态总览

```text
INTAKE
  → DIVERGE
  → SEARCH
  → COMPARE
  → DRAFT
  → CONFIRM
  → GATE_CHECK
```

允许回退：

- `DIVERGE → INTAKE`：初始意图或范围需要重述。
- `SEARCH → DIVERGE/INTAKE`：候选方向无效，或调研改变了问题定义。
- `COMPARE → SEARCH/DIVERGE`：证据不足或需要新候选方案。
- `DRAFT → COMPARE/SEARCH/INTAKE`：合同草案暴露可行性、证据或目标问题。
- `CONFIRM → DRAFT`：用户要求修改合同；若目标发生实质变化，继续回退到最早受影响状态。
- `GATE_CHECK → CONFIRM/DRAFT/SEARCH`：确认、结构或证据门禁未通过。

跳过中间状态必须在 `research/decisions.yaml` 记录理由，并证明该状态的必需输出已由现有、可核验证据满足；不能仅以“任务简单”为理由跳过确认或门禁。

## 渐进式需求获取协议

Codex 不得把用户的一句宽泛方向直接改写成最终研究合同，也不得在头脑风暴前用数据集、baseline、指标或资源分配问题把方向过早固定。`INTAKE` 只取得能够开始交流的研究种子和明确硬边界；`DIVERGE` 由 Codex 主动提问并逐步澄清方向层字段；数据、评测和执行条件允许在 `SEARCH`、`COMPARE` 后继续保持暂定，到 `DRAFT` 才必须形成可确认方案。

`RESEARCH.md` 的“需求获取清单”按依赖关系记录以下十一项，但这不是要求用户一次回答的问卷：

1. 用户研究意图；
2. 研究对象；
3. 核心问题；
4. 预期贡献；
5. 成功标准；
6. 数据条件；
7. baseline；
8. 指标；
9. API/GPU；
10. 数据许可和隐私；
11. 范围外事项。

Codex 根据用户上一轮回答选择信息增益最高的下一问，原则上每轮只问一个核心问题；必要时可以列出少量例子帮助用户理解，但不能要求用户自己设计下一组问题。用户主动提前提供的信息可以立即记录，不要求重复回答。每项使用 `已澄清`、`暂定`、`待澄清`、`明确未知` 或带理由的 `不适用`：

- `已澄清`：用户已经给出足以支持下一步工作的具体信息，但不自动等于最终字段确认。
- `暂定`：当前有可工作的候选值，仍需调研或用户取舍。
- `待澄清`：尚未获得可使用的信息。
- `明确未知`：用户与 Codex 已识别未知项，并使用 `OPEN-<nnn>` 记录解决条件。
- `不适用`：必须说明为什么与当前研究无关。

进入 `DIVERGE` 前只要求“用户研究意图”具有可工作的种子值；研究对象、核心问题和预期贡献正是在发散过程中形成的。进入 `SEARCH` 前，前四项必须达到 `已澄清`、`暂定`、`明确未知` 或带理由的 `不适用`，且不得仍为 `待澄清`；其余字段可以继续待澄清。进入 `DRAFT` 前十一项必须达到 `已澄清` 或带理由的 `不适用`。需求获取确认的是“输入已被正确理解”，不替代 `CONFIRM` 中对最终方向、数据、指标、阶段二资源方案和授权的正式确认。

## Codex 主导的头脑风暴协议

`DIVERGE` 不是一次性列出候选，而是 Codex 主导的渐进式访谈。Codex 应优先从尚未探索的维度提问：研究动机或痛点、目标现象、现有方法的不足、期望解释还是改进、可接受的贡献形式、失败模式、应用场景、负面结果价值和可证伪方式。每轮回答后：

1. 提炼用户新增信号，不把 Codex 自己的建议写成用户确认；
2. 生成、拆分或修订至多两个候选方向；
3. 按研究对象、核心问题、方法机制、预期贡献和验证方式五个差异维度与已有候选比较；
4. 在“头脑风暴记录”中保存问题焦点、用户回答摘要、新增差异维度、关联方向和趋同判断，不复制完整对话；
5. 若本轮没有新增实质维度，明确标记为 `趋同`，并换一个尚未探索的维度继续一次；若连续两轮趋同，或所有新想法均可归入已有方向，询问用户是否还有更多想法；
6. 用户表示暂时没有更多想法后，记录发散结论，整理至少两个实质不同候选，再进入 `SEARCH`。用户希望继续时不得擅自结束发散。

纯头脑风暴不触发具体数据选择、GPU/API 分配、付费额度或研究周期确认。只有某个问题将立即触发外部传输、付费访问、受限资料或其他不可逆风险时，才提前询问该项最小必要授权。

## 多候选方向协议

每轮研究设计必须至少形成两个 `DIR-<nnn>` 候选方向，即使用户最初只给出一个偏好。候选方向必须在研究对象、核心问题、方法机制、预期贡献或验证方式上至少存在一项实质差异，不能只改标题、措辞、具体数据集或资源数量。

每个候选方向至少比较：研究价值、创新性风险、数据需求、计算成本、验证难度和预计交付物。`SEARCH` 可以并行调研多个候选，`COMPARE` 必须展示同口径比较并记录用户选择或否决。进入 `DRAFT` 前必须满足：

- 恰好一个方向标记为 `已选定`；
- 其他候选全部标记为 `已否决`，并记录具体原因；
- 最终方向关联当前研究问题和 `DEC-<nnn>`；
- `research/decisions.yaml` 保存候选方案、否决原因和用户确认来源。

不得让多个候选方向共享“最终方向”身份进入阶段二。用户希望合并方向时，应生成一个新的、边界明确的候选方向作为唯一 `已选定` 项，并把原候选作为独立方案标记为 `已否决`，说明其内容如何被吸收或舍弃。阶段切换后，候选比较可压缩为简短表格和决策引用，但不得删除否决理由或重新采用旧方向而不创建新决策。

## INTAKE：研究意图接收

### 进入条件

- 当前阶段为“阶段一：调研与设计”。
- 用户提出基本研究方向，或明确授权通过头脑风暴协助定义方向。
- 不要求用户在对话中提供真实凭据。

### Codex 必须完成的动作

- 阅读 `README.md`、`AGENTS.md`、`RESEARCH.md`、本协议和工作流门禁。
- 区分用户明确提供、Codex 推断、已有证据和未知信息。
- 只记录可开始头脑风暴的研究种子、用户已明确的动机和硬性禁止事项，不在此时追问具体数据集、baseline、指标、API/GPU 分配、费用上限或研究周期。
- 识别隐私、许可、数据外发、费用、受限访问和领域方法学风险。
- 为缺失信息创建 `OPEN-<nnn>`，不填充虚构答案。

### 用户需要确认的内容

- Codex 对初始意图和硬约束的复述是否准确。
- 哪些内容属于明确要求，哪些只是允许继续探索的方向。

该确认只允许进入发散调研，不等于最终方向确认。

### 输出

- `RESEARCH.md` 中精简的初始意图、约束、字段状态和未决问题。
- 本轮会话恢复摘要。

### 停止条件

- 用户尚未给出可识别的研究方向且不授权头脑风暴。
- 继续需要真实凭据、未授权受限资料或必须由用户决定的隐私/许可边界。

### 下一状态

- 正常进入 `DIVERGE`。
- 停止条件解除前保持 `INTAKE` 或将阶段标记为已暂停。

## DIVERGE：候选方向发散

### 进入条件

- 初始研究意图和硬约束已经得到准确复述。
- 关键未决问题不会阻止提出安全、非执行性的候选方向。

### Codex 必须完成的动作

- 按“Codex 主导的头脑风暴协议”逐轮主动提问，而不是等待用户自行提出研究问题。
- 从回答中提出至少两个具有 `DIR-<nnn>` 的实质不同候选研究方向；用户偏好某一方向也不能跳过对照候选。
- 对每个方向说明核心问题、研究价值、创新性风险、数据需求、计算成本、验证难度、预计交付物和主要失败风险。
- 主动提供低成本、非训练或非 AI 替代路线（适用时）。
- 记录精简的头脑风暴轮次、差异维度、趋同判断、发散结论、候选方向和用户已否决方案，避免首个建议形成无记录锚定。

### 用户需要确认的内容

- 是否还有不同角度希望继续探索；当新想法趋同时，用户可以选择继续或结束发散。
- 结束发散后，哪些候选方向允许进入调研比较；哪些方向被明确否决或暂不考虑。

允许调研某个方向不等于确认其为最终研究目标。

### 输出

- 头脑风暴记录、发散结论、候选方向及比较维度。
- `RESEARCH.md` 中的暂定字段和否决摘要。
- 需要调研的问题与计划查询范围。

### 停止条件

- 所有候选方向都违反权限、伦理、许可或用户硬约束。
- 候选方向依赖尚未获得的受限数据或外部传输授权。

### 下一状态

- 用户确认暂时没有更多想法、已记录发散结论且有至少两个可调研候选方向时进入 `SEARCH`。
- 初始意图需要重述时回到 `INTAKE`。

## SEARCH：调研与证据建立

### 进入条件

- 至少两个实质不同的候选方向及其待回答问题已经登记。
- 检索范围、外部服务、数据外发和费用边界允许执行计划中的调研。

### Codex 必须完成的动作

- 按 `docs/SEARCH_PROTOCOL.md` 为每个候选方向覆盖背景、现有方法、baseline、研究空白、失败/负面结果、数据集/指标、许可/可行性和相似工作。
- 使用中英文、同义词、方法词和反证词扩展查询，并执行向前/向后引用追踪或记录不可执行原因。
- 每次实际检索追加 `QRY-<nnn>`；正式来源登记 `SRC-<nnn>`；最小事实主张登记 `CLM-<nnn>`。
- 在 `research/search_coverage.yaml` 登记各 `DIR` 的类别覆盖、范围、独立来源增量、方法类别、反证和停止代理指标。
- 区分原始与二手来源、一级至五级质量、独立与同源证据、直接支持与模型推论；二手来源追溯原始出处。
- 检查来源日期、版本、许可、访问状态、更新和撤稿，并逐项核验引用位置、数字/单位、范围与因果措辞。
- 保留冲突和不利证据，分类冲突原因；证据不足时保持未决。
- 在 `research/resources.yaml` 更新实际累计资源与不可得指标说明；阶段一不设置查询、页面、调用、费用、抽取、摘要、合同体积、证据存储或研究周期上限。
- 先抽取结构化主张再压缩上下文，去除重复结果；压缩后回查原始来源，不删除关键限制、授权、否决方案或引用 ID。

### 用户需要确认的内容

- 是否允许使用用户提供或私有来源。
- 是否允许必要的外部传输、付费检索或受限访问。
- 调研范围是否需要扩展或缩减。

### 输出

- `research/search_log.jsonl`、`search_coverage.yaml`、`sources.yaml`、`claims.yaml` 和 `resources.yaml` 中的真实证据及资源记录。
- 按候选方向整理的证据、反证、冲突和未决项摘要。

### 停止条件

- 关键来源不可访问、许可不明、存在未授权外发或敏感内容风险。
- 核心主张只有不可核验来源，或来源冲突足以阻止继续比较。

### 下一状态

- 八类覆盖、反证、计划范围和可观察停止代理指标足以解释停止搜索时进入 `COMPARE`；不得声称完全检索。
- 需要新方向时回到 `DIVERGE`；问题定义变化时回到 `INTAKE`。

## COMPARE：候选方向比较

### 进入条件

- 每个仍在考虑的方向均有足够的正面证据、反证和可行性信息。
- 已披露尚未覆盖的数据库、语言、时间或受限资料边界。

### Codex 必须完成的动作

- 比较研究价值、新颖性风险、数据可得性、方法可行性、baseline 强度、评测可证伪性、成本和安全边界。
- 不把“未检索到”写成“没有相关研究”。
- 显式列出每个方向的优势、局限、失败条件和残余未知。
- 将持久选择、否决理由和支撑主张写入 `research/decisions.yaml`。

### 用户需要确认的内容

- 从候选中选择唯一最终方向，或要求生成一个边界明确的合并方向；同时确认其余方向的否决理由。
- 对研究价值、成本、风险和交付物的取舍。

### 输出

- 唯一 `已选定` 方向及全部 `已否决` 方向的同口径比较。
- `DEC-<nnn>` 决策证据链。
- 候选研究问题、贡献和范围边界。

### 停止条件

- 没有方向同时满足证据、资源和权限约束。
- 用户尚未在实质不同的选项之间作出方向选择。

### 下一状态

- 恰好一个方向已选定、其余方向均已否决并具有决策记录后进入 `DRAFT`。
- 证据不足时回到 `SEARCH`；需要新方案时回到 `DIVERGE`。

## DRAFT：研究合同草拟

### 进入条件

- 研究方向已经明确选择或组合，并有可追溯决策证据。
- 数据、baseline、指标和资源至少存在可填写的候选方案。

### Codex 必须完成的动作

- 精简填写 `RESEARCH.md`，不复制详细调研过程。
- 为研究问题、数据、baseline、指标、成功标准、决策、证据和授权分配稳定 ID。
- 建立“研究问题 → 数据 → baseline → 指标 → 成功标准 → 计划实验”的关系。
- 标注每个关键字段的信息来源、确认状态、确认日期/轮次、决策和证据 ID。
- 生成关联相同研究问题与成功标准的 `experiments/TODO.md` 草案。

### 用户需要确认的内容

- 草案是否完整表达所选方向，是否可以进入逐项确认。
- 需要修改或重新调研的字段。

该确认只表示草案可审阅，不替代字段级确认。

### 输出

- 当前研究合同草案。
- 阶段二任务草案。
- 尚未确认或冲突字段清单。

### 停止条件

- 研究问题无法关联可获得数据、baseline、指标或可执行实验。
- 草案依赖未经核验的关键主张。

### 下一状态

- 草案结构完整后进入 `CONFIRM`。
- 发现方向问题时回到 `COMPARE`、`SEARCH` 或 `INTAKE`。

## CONFIRM：字段级确认

### 进入条件

- 合同草案已包含所有阶段二进入门禁要求的字段。
- 用户可以看到确认对象、值、依据、影响和未决风险。

### Codex 必须完成的动作

- 按“方向、数据、指标、阶段二资源方案、授权”五类分别请求确认。
- 每次说明本次确认覆盖的字段和稳定 ID，不扩大到未列出的内容。
- 将偏好和研究取舍记录为 `DEC-<nnn>`；将外发、费用、受限访问及其他权限记录为 `AUTH-<nnn>`。
- 对模糊肯定只记录为 `暂定` 或 `待确认`，不得提升为 `已确认`。
- 任一关键字段改变后，按依赖关系重新检查并使受影响的下游确认失效。

### 用户需要确认的内容

- 方向确认：研究目标、研究问题、预期贡献和范围外事项。
- 数据确认：数据来源、版本、许可、分类、隐私、外发和保留规则。
- 指标确认：baseline、指标、统计口径、阈值、消融和稳健性验证。
- 阶段二资源方案确认：实验所需 GPU/API 职责、调用或费用边界和失败停止规则；阶段一无固定资源上限，也不要求研究周期或截止日期。
- 授权确认：付费使用、外部传输、受限访问、依赖安装和授权门禁产物。

### 输出

- 所有关键字段的字段级确认状态。
- 对应的 `DEC`、`AUTH`、确认日期/轮次与证据引用。
- 因字段变化被重新打开的未决问题。

### 停止条件

- 任一关键字段仍为 `暂定`、`待确认` 或 `存在冲突`。
- 用户表达无法明确对应具体字段或授权范围。

### 下一状态

- 全部关键字段明确后进入 `GATE_CHECK`。
- 用户修改合同则回到 `DRAFT`，必要时继续回退。

## GATE_CHECK：门禁检查与交接

### 进入条件

- 关键字段均为 `已确认` 或带明确理由的 `不适用`。
- 合同关系、阶段一证据和阶段二任务草案已经形成。

### Codex 必须完成的动作

- 检查字段确认、用户授权、数据/隐私、阶段二资源方案、证据核验、稳定 ID、连续阶段切换和合同关系。
- 执行 `uv run python scripts/validate_workspace.py --strict`。
- 检查会话恢复摘要完整且与当前合同一致。
- 明确列出仍存在但不阻塞的局限、未覆盖范围和风险。
- 记录阶段切换 `TRANS-<nnn>` 及其决策/授权依据。

### 用户需要确认的内容

- 当前合同是否作为阶段二执行依据。
- 是否同意在已记录的资源、数据和授权边界内进入阶段二。

### 输出

- 已通过或未通过的阶段一门禁结果。
- 可执行的 `experiments/TODO.md`。
- 最新会话恢复摘要和阶段切换记录。

### 停止条件

- 严格验证失败。
- 合同、证据、授权或恢复摘要不一致。
- 出现需要用户新决策、权限或阶段二资源方案的问题。

### 下一状态

- 门禁与用户确认均通过后进入阶段二。
- 否则回到 `CONFIRM`、`DRAFT` 或 `SEARCH` 中最早受影响状态。

## 确认协议

### 什么构成明确确认

明确确认必须能够识别：

- 确认类型；
- 覆盖字段或稳定 ID；
- 当前值或允许范围；
- 用户表达所在日期或轮次；
- 相关决策或授权 ID；
- 对后续阶段的影响。

“可以考虑”“方向不错”“先看看”“可以试试”“差不多”“暂时这样”等表达只允许继续探索或形成暂定草案，不能解释为研究合同、费用、外发、受限访问或高风险操作的正式确认。

### 确认类型与记录位置

| 确认类型 | 最少覆盖内容 | 主要记录 |
| --- | --- | --- |
| 方向确认 | 目标、研究问题、贡献、范围 | `RESEARCH.md` 字段状态 + `DEC-<nnn>` |
| 数据确认 | 数据、版本、许可、隐私、外发、保留 | 字段状态 + `DEC-<nnn>`；涉及权限时加 `AUTH-<nnn>` |
| 指标确认 | baseline、指标、阈值、消融、稳健性 | 字段状态 + `DEC-<nnn>` |
| 阶段二资源方案确认 | GPU/API 职责、必要上限、费用和失败停止规则 | 字段状态 + `DEC-<nnn>`；涉及付费时加 `AUTH-<nnn>` |
| 授权确认 | 付费、外发、受限访问、依赖、授权门禁产物 | `AUTH-<nnn>`，并关联适用 `DEC-<nnn>` |

一般性同意不能跨确认类型传播。例如，确认研究方向不代表确认数据外发；确认 API 模型不代表确认费用；允许读取本地资料不代表允许上传外部服务。

### 关键字段变化后的失效传播

| 变化 | 至少重新检查的内容 |
| --- | --- |
| 研究目标或研究问题 | 贡献、数据、baseline、指标、成功标准、阶段二资源方案、证据、全部阶段二任务 |
| 数据或许可/隐私边界 | 数据可用性、指标可计算性、API 数据流、授权、实验任务 |
| baseline | 贡献声明、指标比较、成功标准和实验任务 |
| 指标或统计口径 | 数据需求、成功标准、实验任务和论文预期主张 |
| 阶段二资源方案 | 实验范围、资源职责、停止规则和阶段二任务 |
| 授权或外发边界 | 所有依赖该权限的 Skill、API、数据流和实验；必要时立即暂停 |

受影响字段先降为 `待确认` 或 `存在冲突`，完成重新检查后才能恢复为 `已确认`。实质性范围变化按工作流门禁回退到阶段一。

## 会话恢复协议

每轮阶段一交互结束前，Codex 必须更新 `RESEARCH.md` 的“会话恢复摘要”，至少包含：

- 当前全局阶段与阶段一子状态；
- 当前候选方向与唯一选定方向（尚未选定时明确写“无”）；
- 本轮已确认事项；
- 本轮否决方案；
- 当前暂定假设；
- 新增证据；
- 未解决问题；
- 下一轮首要任务；
- 不应重新采用的旧方案。

处于 `DIVERGE` 时还必须记录头脑风暴状态、最新趋同判断和用户是否还有更多想法。摘要中的阶段、候选、选定/否决方向、未决问题和稳定 ID 必须与正文表格一致；不能用自由文本同时声称“尚无候选”和“已选定方向”。

没有某类内容时写明“无”及原因，不留含糊空白。摘要只保存稳定 ID 和必要说明，不复制完整聊天、搜索结果或来源全文。

新会话恢复顺序：

1. 阅读 `README.md`、`AGENTS.md`、`RESEARCH.md`、本协议和工作流门禁。
2. 核对当前阶段一子状态、字段状态、未决问题、决策、授权和恢复摘要。
3. 检查摘要中引用的 `SRC`、`CLM`、`DEC`、`AUTH` 是否仍可解析。
4. 对比当前合同与“不得重新采用”的旧方案，避免恢复已否决方向。
5. 从“下一轮首要任务”继续；若摘要与合同冲突，先停止并修复状态，不自行选择版本。

恢复摘要是当前会话交接，不是不可变历史。更新时以当前合同和证据为准；持久决策、查询和来源历史仍分别保存在 `research/decisions.yaml`、`search_log.jsonl` 与 `sources.yaml`。
