# 三阶段 Skill 使用规则

本文档是仓库级 Skills 的发现、选择、阶段适用性和授权边界的事实来源。Skill 是否使用首先由当前任务决定，而不是由阶段名称自动决定；阶段规则只限制何时允许使用、需要哪些前置条件，以及产物应归属到哪里。

## 调用原则

1. 用户显式指定 Skill 时，Codex 应优先使用；若缺少授权、依赖、凭据或数据外发许可，先暂停并说明恢复条件。
2. 用户未指定时，Codex 可根据 Skill 的 `description` 与实际任务自动选择，但不得仅因进入某个阶段就调用全部 Skills。
3. `AGENTS.md`、`docs/WORKFLOW_GATES.md`、本文件和用户当前指令的安全、隐私、预算与交付边界高于 Skill 内部的一般操作建议。
4. Skill 只提供执行工作流，不代替研究决策、阶段门禁、运行证据或用户授权。使用 Skill 产生的研究内容仍必须写入规定的动态文件或运行目录。
5. Skill 所需依赖按需检查。安装或删除依赖前遵循 `AGENTS.md` 的依赖策略；不得因为 Skill 存在就预装所有 OCR、Office 或绘图工具。
6. 外部服务只检查所需环境变量是否已配置，不读取、显示或记录真实值。未确认数据可以外发时，不得调用会上传本地文件的 Skill。

| --- | --- | --- | --- | --- | --- |
| `pdf` | 本地读取、分析、拆分、合并、生成或表单处理 PDF | 可处理用户提供的普通文本 PDF | 可处理实验协议、报告或本地结果 PDF | 仅在用户要求 PDF 交付或转换时使用 | 检查许可证、受限内容和所需本地依赖；复杂扫描论文优先结构化解析 |
| `paddleocr-doc-parsing` | 复杂 PDF、扫描文档、表格、公式、多栏和版面解析 | 可用于论文与资料结构化 | 可用于已批准的文档型数据预处理 | 可用于核对来源，不作为默认写作工具 | 必须确认外部传输授权、调用预算和 `PADDLEOCR_ACCESS_TOKEN` 已配置；不得输出令牌 |
| `paddleocr-text-recognition` | 图片、截图、简单扫描件的逐行文字或坐标识别 | 可提取简单研究资料文字 | 可用于已批准的 OCR 数据准备或检查 | 仅在来源核对确需逐行文字时使用 | 与结构化解析相同的外发、预算和凭据门禁；表格、公式、多栏文档不用它 |
| `paper-skill-creater` | 用户明确要求把一篇论文制作成可复用 paper Skill | 主要创建阶段；用于已确认的核心论文 | 可复用已创建 Skill 核对方法、设置与对比 | 可复用已创建 Skill 辅助引用和相关工作 | 创建会修改 `.agents/skills/`，必须获得明确授权；确认全文保存、版权、许可和外发边界；OCR 结果必须回查原文；全文与来源默认不提交 |
| `xlsx` | 读取、分析、创建或修改表格文件 | 可分析用户提供的数据字典、预算和清单 | 可用于实验数据分析、指标汇总和可视化表格 | 仅在论文表格或用户要求表格交付时使用 | 保留既有模板和公式；核对公式错误；安装 LibreOffice 等依赖前确认 |
| `docx` | 读取、创建、修改、批注或修订 Word 文档 | 可读取用户提供的需求或研究材料 | 通常不使用；仅在实验输入或协议确为 DOCX 时使用 | 仅在用户要求 Word 稿、批注或修订稿时生成 | 正式文档属于可选交付物；保留修订痕迹，安装 Office 工具依赖前确认 |
| `pptx` | 读取、创建或修改演示文稿 | 可读取用户提供的汇报或需求材料 | 通常不使用；仅在实验输入或评审材料确为 PPTX 时使用 | 仅在用户要求答辩、汇报或演示文稿时生成 | 演示文稿不是默认论文交付；使用模板、图片和字体前确认许可，安装大型依赖前确认 |

仓库中的 `.agents/skill-creator/` 是迁移前保留的非活动维护参考，不在 Codex 的仓库级自动发现目录中。创建或更新 Skill 时使用当前环境提供的 `skill-creator`；不要在普通研究阶段自动调用本地旧副本。

## 分阶段规则

### 阶段一：调研与设计

- 根据真实输入格式选择读取类 Skill；没有对应文件或任务时不调用。
- 开始 OCR 或其他外部解析前，在 `RESEARCH.md` 记录数据分类、允许外发范围、预算和授权。
- 只有用户明确希望长期复用某篇论文时，才创建 paper Skill；普通论文阅读不自动产生 `.agents/skills/paper-*`。
- Skill 参与阶段一调研时，仍须遵循 `docs/SEARCH_PROTOCOL.md`。将实际查询、方向覆盖、正式来源、可核验主张、持久决策和累计资源分别登记到 `research/search_log.jsonl`、`research/search_coverage.yaml`、`research/sources.yaml`、`research/claims.yaml`、`research/decisions.yaml` 与 `research/resources.yaml`；工具调用、返回字符或 token、页面、时间和估算费用计入同一预算。Skill 结果必须回查原始来源，不能把模型输出或工具置信度当作真实性证明，也不得将 OCR 全文、工具原始响应或受限材料直接放入活动上下文或可提交证据。在 `RESEARCH.md` 只保留稳定 ID 摘要，并把本轮新增 ID 写入会话恢复摘要。
- 在阶段一结束前，将阶段二确实需要的 Skill、依赖与授权登记到 `RESEARCH.md` 和 `experiments/TODO.md`；不预生成不适用任务。

### 阶段二：实验与分析

- Skills 只辅助已批准的数据准备、文件处理和分析，不代替独立实验脚本与不可变运行记录。
- Skill 参与实验数据流时，在实验脚本说明用途，并在运行元数据记录非敏感工具名称、版本和产物路径。
- 外部 OCR 失败、额度耗尽或依赖缺失时记录失败并停止相关步骤，不得静默换用其他外部服务或模型。
- Office 文档 Skill 仅在实际输入格式需要时使用；默认实验分析代码仍放在 `src/`、`scripts/` 或 `experiments/scripts/`。

### 阶段三：论文写作

- 已创建的 paper Skill 可用于定位原文和引用线索，但所有引用、实验数字和结论仍需回到原始论文或本项目运行证据核验。
- `docx`、`pptx`、`xlsx` 和 PDF 生成属于可选交付方式，只有用户明确要求时才创建；默认仍维护 `paper/draft_zh.md`。
- 不得让格式转换扩张论文范围、删除不利结果或把未验证内容变成正式结论。
- 正式稿、演示文稿或其他对外文件完成前，执行隐私、凭据、许可证和实验 ID 追溯检查。

## 输出与停止规则

- OCR 或文档 Skill 的“完整输出”建议不得覆盖最小披露原则。未请求或不允许展示全文时，只保存和展示授权范围内的必要内容。
- 缺少真实文件、依赖、外部传输授权、预算、用户要求的输出格式或合法保存权限时，不猜测、不伪造、不自动扩大范围。
- Skill 的命令、缓存、解析 JSON 和中间文件应进入对应的已授权本地数据目录或新的运行目录，不写入 `RESEARCH.md`、可提交阶段一证据、`.env` 或历史运行记录；活动上下文只保留去重后的结构化主张和必要证据定位。
- 新增、删除或改变 Skill 的触发范围属于模板维护任务，必须同步检查本文件、`README.md`、`AGENTS.md`、`docs/TEMPLATE_BOUNDARIES.md` 和验证器。
