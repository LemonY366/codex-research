# 实验运行脚本

本目录存放**每次实验运行对应的可执行脚本**。每个实验的具体实现都必须持久化为一个独立脚本，而不能只存在于聊天记录、Notebook 单元格、终端历史或对共享源码的临时修改中。

## 核心要求

- 每次运行都创建或明确引用一个脚本，例如 `exp-001-baseline.py`、`exp-002-lr-sweep.py`。
- 脚本应可从仓库根目录直接运行，例如：

  ```bash
  uv run python experiments/scripts/exp-001-baseline.py \
    --seed 1337 \
    --output-dir experiments/runs/run-20260718-001-baseline
  ```

- 同一脚本应在输入、配置与随机种子相同的条件下产生可复现的行为。
- 不要在完成运行后覆盖旧脚本；新的实现、新的假设或新的参数组合应创建新脚本或保留明确版本。
- 在 `experiments/runs/` 的对应运行记录中，登记所用脚本路径、配置路径、命令、Git 提交和输出指标。

## 脚本约定

- 在文件开头说明实验 ID、目的、API 与 GPU 的使用情况和用途、二者的数据流、预算限制、输入、输出和运行命令。
- 接收显式的 `--config`、`--seed`、`--output-dir` 等参数；不要依赖未记录的本地状态。
- 将日志、指标和检查点写入该次运行专属的输出目录，不要覆盖其他实验产物。
- 记录数据集与模型版本、随机种子、运行环境和关键超参数。
- 缺少数据、配置无效、显存不足或预算受限时，应清晰失败并返回非零状态码。
- 不得读取 `.env`、打印环境变量、输出密钥或在脚本中硬编码凭据。

### 文件头资源声明

每个实验脚本都必须在顶层 docstring 中声明以下内容；某类资源未使用时，明确标记为“否”或“不适用”，不要省略字段：

- 实验 ID 与实验目的。
- 是否使用外部 API；如使用，说明用途、协议、模型名称的配置来源和所需环境变量名称，但不记录配置值或密钥。
- 是否使用 GPU；如使用，说明用途和所需的本地模型或检查点。
- API 与 GPU 之间的数据流和执行顺序。
- GPU 时间、API 调用次数、API 费用或其他适用的预算限制。
- 输入、输出、运行命令与对应运行记录的预期位置。

具体字段由 Codex 根据 `RESEARCH.md` 中已与用户确认的资源设计生成。一个同时使用 API 和 GPU 的脚本可参考：

```python
"""
实验 ID：exp-001
目的：评价本地模型在指定数据集上的回答质量。

资源：
- 使用 GPU：是；用于本地模型推理。
- 使用 API：是；用于对本地模型输出进行评分。
- API 协议：OpenAI-compatible。
- API 配置：仅通过 `LLM_API_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL` 环境变量提供；不得记录或输出其值。
- 数据流：输入数据 -> GPU 本地推理 -> API 评分 -> 汇总指标。

预算：
- GPU 时间：从 `RESEARCH.md` 读取已确认限额。
- API 调用和费用：从 `RESEARCH.md` 读取已确认限额。

输入：TODO（数据集路径与版本）。
输出：`experiments/runs/<run-id>/` 中的日志、元数据、指标和实验产物。
运行命令：TODO（根据本脚本参数填写）。
"""
```

文件头只能记录环境变量的名称和用途，不能包含真实 API key、完整环境变量值或其他凭据。

## 命名建议

使用稳定的实验 ID 和简短描述，便于论文和结果表追溯：

```text
exp-001-baseline.py
exp-002-larger-batch.py
exp-003-no-augmentation.py
```

通用数据预处理与环境检查脚本不属于这里，应放在 `scripts/` 或数据集对应目录；论文数据图生成脚本应放在 `paper/images/scripts/`。这里的每个脚本都应能回答一个明确的实验问题，并能被单独重新执行。
