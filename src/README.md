# 论文源码

`src/` 存放支撑论文方法、实验和复现的核心源码，包括模型实现、数据适配、训练与评测逻辑、推理流程和指标计算。论文中描述的方法与实验结论应能够追溯到此目录中的实现。

## 适合放在这里的内容

- 论文提出的方法、模型模块、算法和损失函数实现。
- 可复用的数据读取、预处理适配和特征构建代码。
- 通用训练循环、评测流程、推理逻辑和指标计算。
- 与论文方法直接相关的配置解析、实验组件和类型定义。

建议按职责组织，例如：

```text
src/
├── models/        # 模型与方法实现
├── data/          # 数据读取与适配
├── training/      # 训练循环与优化逻辑
├── evaluation/    # 评测与指标计算
├── runtime/       # 阶段二/三共享的结构化进度与心跳
└── utils/         # 被多个模块使用的小型工具
```

## 与其他目录的边界

- `src/` 提供可复用的论文源码；不要在此保存某次实验独有的运行入口。
- `experiments/scripts/` 保存每个实验对应的可直接执行脚本，并调用 `src/` 中的实现。
- `experiments/runs/` 保存实际运行产生的日志、配置快照、指标和其他结果。
- `scripts/` 保存数据预处理、环境检查等跨实验通用辅助脚本。
- `paper/` 保存草稿、正式论文、参考文献与论文图像，不应复制代码实现。
- `runtime/progress.py` 提供实验与写作共用的原子状态、追加事件、心跳和归档接口；具体任务仍由实验脚本或写作流程定义。

## 实现要求

- 方法名称、参数含义和行为应与 `paper/draft_zh.md` 中的论文表述一致。
- 使用显式配置、随机种子和输入路径，避免隐藏的全局状态。
- 为关键模块提供最小可验证接口；修改方法实现后，应通过相关实验脚本重新运行验证。
- 不得在源码中硬编码数据路径、API 密钥、令牌或机器特定设置。
- 运行时产生的检查点、日志和大文件不应写入 `src/`。

当论文方法发生实质性变化时，应先更新源码和实验实现，再根据已验证结果修改论文草稿；不得只修改论文叙述而不更新对应实现。
