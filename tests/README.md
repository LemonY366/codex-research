# 验证器回归与端到端测试

`tests/` 使用 Python 标准库 `unittest` 验证 `scripts/validate_workspace.py` 自身。测试不会执行真实检索、调用外部服务、读取 `.env`、运行实验或创建正式研究 registry。

运行命令：

```bash
python3 -m unittest discover -s tests -v
```

## 验证范围

### 迁移与阶段状态

- 新模板在研究目标尚未确定时允许保留 `待确认`。
- 尚未出现的方向、研究对象、证据、决策和授权保持空表或不创建对象表，不使用虚构占位记录。
- High 的方向专用窗口及其中的方法交流不产生仓库写入；结构验证从 Medium 持久化实质交接后开始，正式搜索和证据仍受完整门禁约束。
- 阶段一 `DIVERGE` 等中间状态允许按门禁保存部分进度，但不能绕过错误。
- 宽泛方向不能跳过 Codex 主导的逐轮头脑风暴直接进入合同草拟。
- 非正式想法无需建档；只有通过轻量侦察并值得正式比较的方向才登记 `DIR-<nnn>`。一个正式方向也可以进入搜索，但 `DRAFT` 和阶段二前只能有一个最终方向。
- 关键字段为 `待确认` 或 `存在冲突` 时阻止阶段二。
- 空的阶段一证据集合合法；未出现真实对象时不要求 dataset、model、baseline 或 experiment registry。
- 缺少阶段一子状态的旧合同返回明确迁移错误。
- 机器状态、Markdown 投影与追加式转换账本必须一致，不能通过只改 `RESEARCH.md` 提前进入后一阶段。
- 阶段二门禁要求失败停止规则、实际用量计量和必要授权。

### 阶段二/三执行与证据交接

- 任务状态、追加事件和心跳结构完整；运行中超过 120 秒未刷新心跳会产生警告。
- 实时进度生命周期不会读取或改写阶段二、阶段三的 `TODO.md`，两者继续保持原有任务记录方式。
- registry 与本地运行目录双向一致，未登记运行和不存在的登记运行均被拒绝。
- 阶段三入口要求已核验的阶段二证据交接及本地成功运行；阶段三完成要求成功的写作会话。
- 成功运行必须具备命令、配置、环境、日志、指标、进度归档、数据版本/校验和与随机种子；GPU 运行还需 CUDA/PyTorch、GPU 时间、峰值显存和训练步数。

### 安全与隐私

- 查询和证据中的凭据字段被拒绝。
- `.env` 即使对 Git 可见也只报告路径风险，不读取内容。
- 全文、原始样本、提示/响应正文和敏感样本字段被拒绝。
- 过长证据摘要和常见个人信息模式被拒绝。
- 允许外部 API 传输时必须存在范围明确的 `AUTH-<nnn>`。

这些是结构化安全防线，不替代人工隐私审查、数据分类、来源真实性核验或专业密钥扫描。

### 搜索与真实性

- 每个正式入围方向必须记录八类搜索覆盖、中英文关键词、引用追踪和明确停止类型；证据饱和要求完整代理，可行性阻断要求可回查来源与未覆盖范围，且被阻断方向不能入选。
- `GATE_CHECK` 会启用完整合同、证据、恢复摘要和 TODO 门禁；更早子状态中的严格验证通过不能代表阶段一完成。
- 二手来源必须追溯原始出处，同源转载不能作为独立交叉证据，低质量线索不能单独支撑合同。
- 合同主张必须完成引用位置、数字/范围、因果措辞和模型推论边界检查；冲突需保留原因和不利证据。
- 活动搜索日志达到 5,000 条或 2 MiB 时产生轮转预警，归档与活动查询 ID 保持全局唯一。

## 合成端到端演练

端到端测试在操作系统临时目录复制模板，并在运行时生成一个“公开合成短文本规则分类稳定性”的虚构研究方向，依次形成：

```text
初始工作方向与替代方向检查
→ 轻量侦察后晋升的正式 DIR 与搜索覆盖记录
→ SRC-001
→ CLM-001
→ DEC-001 与字段确认
→ 精简 RESEARCH.md
→ GATE_CHECK
→ 关联 RQ-001 / SC-001 的 exp-001 任务
```

测试确认模板结构与阶段门禁一致、搜索停止依据完整、恢复摘要一致、阶段二任务具有稳定 ID，同时不存在实验运行目录或 `registry.yaml`。临时工作区在测试结束后自动删除，因此合成查询、来源和决策不会进入正式 `research/`，也不会被误认为真实科研证据。
