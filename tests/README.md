# 验证器回归与端到端测试

`tests/` 使用 Python 标准库 `unittest` 验证 `scripts/validate_workspace.py` 自身。测试不会执行真实检索、调用外部服务、读取 `.env`、运行实验或创建正式研究 registry。

运行命令：

```bash
python3 -m unittest discover -s tests -v
```

## 验证范围

### 迁移与阶段状态

- 新模板在研究目标尚未确定时允许保留 `待确认`。
- 阶段一 `SEARCH` 等中间状态允许保存部分进度，但不能绕过错误。
- 关键字段为 `待确认` 或 `存在冲突` 时阻止阶段二。
- 空的阶段一证据集合合法；未出现真实对象时不要求 dataset、model、baseline 或 experiment registry。
- 缺少阶段一子状态的旧合同返回明确迁移错误。

### 安全与隐私

- 查询和证据中的凭据字段被拒绝。
- `.env` 即使对 Git 可见也只报告路径风险，不读取内容。
- 全文、原始样本、提示/响应正文和敏感样本字段被拒绝。
- 过长证据摘要和常见个人信息模式被拒绝。
- 允许外部 API 传输时必须存在范围明确的 `AUTH-<nnn>`。

这些是结构化安全防线，不替代人工隐私审查、数据分类、来源真实性核验或专业密钥扫描。

## 合成端到端演练

端到端测试在操作系统临时目录复制模板，并在运行时生成一个“公开合成短文本规则分类稳定性”的虚构研究方向，依次形成：

```text
初始方向与候选方案
→ QRY-001
→ SRC-001
→ CLM-001
→ DEC-001 与字段确认
→ 精简 RESEARCH.md
→ GATE_CHECK
→ 关联 RQ-001 / SC-001 的 exp-001 任务
```

测试确认所有错误和警告均为空、恢复摘要完整、阶段二任务具有稳定 ID，同时不存在实验运行目录或 `registry.yaml`。临时工作区在测试结束后自动删除，因此合成查询、来源和决策不会进入正式 `research/`，也不会被误认为真实科研证据。
